1Scope

This document specifies native DTLS 1.2 protection for unicast SOME/IP over UDP inside the vsomeip library. A service opts in through configuration; application source code does not change. SOME/IP service discovery multicast, TCP transport, local IPC and the SOME/IP wire format are out of scope and stay unchanged.

Out of scope

  • DTLS 1.3
  • DTLS or signing for SD multicast
  • HSM integration (possible later behind dtls::backend)
  • Automatic certificate rotation
  • Post-quantum cipher suites

Terms

  • DTLS: Datagram TLS, RFC 6347 (1.2)
  • SD: SOME/IP Service Discovery
  • EARS: Easy Approach to Requirements Syntax
  • ADR: Architecture Decision Record
  • Peer: a remote (IP address, UDP port) pair

Requirement conventions

Requirements use EARS wording with “shall”. Status is the state on test/dtls-udp as of the document date. Verification names the planned method: UT unit test, CT component test, IT integration test (multi-ECU, fake sockets), QT qualification test (real processes and sockets), ST system test (bench), RV review or inspection.

Implemented in code and exercised Partial code exists but incomplete, unwired or unverified Not met code contradicts the requirement Open not started

5Architecture decisions

ADRDecisionRationale
ADR-001New dtls_udp_server/client_endpoint_impl classes next to the UDP endpoints; existing endpoints untouched.Small blast radius; one CMake switch removes it; reviewable upstream.
ADR-002OpenSSL 3 first, behind a dtls::backend interface.Most mature DTLS stack; allows Mbed TLS or HSM-backed crypto later.
ADR-003One DTLS session per peer (IP, port); the client endpoint holds one session.Matches SOME/IP unicast usage.
ADR-004Opt-in per service with unreliable_secure; unreliable unchanged.Backward compatible; staged rollout; no application changes.
ADR-005SD multicast stays plaintext.No per-peer session exists for multicast; SD signing is future work.
ADR-006Parity with hybrid mode; on conflict, disable DTLS in hybrid mode.Hybrid mode is new upstream behaviour and must not be destabilised.

6.2 Ordered next steps

  1. Record the Linux baseline on 3.7.5. Build in the repository Dockerfile (add libssl-dev) with ENABLE_DTLS=OFF; run ctest -R '^unit_' and the fake-socket tests; save the results. P1 · SWR-DTLS-061
  2. Make the endpoints compile against 3.7.5. Create sockets through the injected abstract_socket_factory; update tp_segmentation_enabled to take service_instance_t; implement any new base-class hooks. P2, P4, P5 · SWR-DTLS-062
  3. Correct the cookie design. Pass the peer address into create_server_session; compute the cookie as an HMAC of the address with a rotating random secret; refuse handshakes if the random generator fails; don't allocate a session before the cookie is verified. SWR-DTLS-023, 024
  4. Bound session state. Enforce handshake_timeout_ms, cap sessions, evict idle ones; make MTU configurable. SWR-DTLS-026, 035, 040
  5. Remove reference cycles. Capture weak_ptr in session callbacks. SWR-DTLS-041
  6. Add unit tests unit_dtls_backend, unit_dtls_session, unit_dtls_configuration in test/unit_tests/dtls_tests/, including wrong CA, expired certificate, loss and reordering. P3 exit · SWR-DTLS-001…027
  7. Wire the configuration. configuration_impl::load_dtls, per-service unreliable_secure, getters and warnings. SWR-DTLS-001…006
  8. Wire endpoint creation and routing. Factory branch in endpoint_manager_impl; serviceinfo mark in routing_manager_impl; decide OI-01 and OI-02 first. SWR-DTLS-010…013
  9. Add component and multi-ECU tests with fake sockets, including hybrid mode, and the hello_world_dtls example. P6 exit · SWR-DTLS-030…034, 070
  10. Add qualification tests on two containers: interop with openssl s_client/s_server, tcpdump check of SD and service ports, 1000-handshake stress, sanitizers, ON and OFF suites. P7 · SYS-DTLS-001…006
  11. Document and publish. Update vsomeipConfiguration.md and the user guide; add the CI matrix for ENABLE_DTLS ON and OFF; request community review. P7
  12. Bench validation on target ECUs: automotive Ethernet MTU, OEM PKI, revocation, peer reboot, CPU and latency budget. SYS.5
